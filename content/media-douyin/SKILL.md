# Media Douyin

本技能处理抖音平台策略、素材发现建议、平台筛选、改编和发布。`media-ops` 先传入账号目标、内容主体、受众、来源边界和发布策略；本技能据此生成抖音专属发现策略，再接收核验后的候选完成平台筛选和发布。

## Build the discovery brief

- 先判断账号是音乐视频、知识口播、生活方式、品牌或其他主体；不同主体使用不同来源和候选标准，不默认抓取全站热度最高的作品。
- 结合账号 operation 生成 `discoveryBrief`：主体、平台目标、首要行为信号、来源组、关键词、排除项、版权边界、时间窗口和排序依据必须可追溯。
- 当来源组包含用户确认授权的创作者或频道时，使用“授权白名单优先”模式：先检查该频道的新作品和相关视频，再考虑主题搜索；不得把频道外的转载结果自动视为同一授权范围。
- 授权创作者候选至少记录频道 URL、视频 URL/ID、原始标题、作者、发布时间、授权状态、署名要求、允许的改编范围和是否允许商业化；授权范围不清时标记为待确认。
- 音乐视频账号优先发现适配音频、明确的前三秒/副歌记忆点、可视化和剪辑空间、可持续复用的音乐素材，并把版权、音源归属和二次使用权限作为硬门禁。
- 知识或产品账号优先发现能在短时长内完成事实钩子、证据解释和行动建议的素材；热点只作为新鲜度信号，不把热搜排名当作选题结论。
- 对科技类账号，优先找“一个变化 + 一个证据 + 一个普通人影响”的可视化主题：官方发布、原始研究、产品演示和带时间戳的原始访谈优先；二手短视频只作为线索。
- 为每个候选记录来源、音频/视频权限、时长、画面可用性、前三秒钩子、信息密度、完播潜力、互动入口、账号相关性和可加入的原创解释；不得用播放量替代视频适配度。
- 顺序处理已授权创作者时，使用可配置的状态文件记录 `creatorId`、排序方向、上次成功发布的视频 ID、下一候选 ID、来源 URL 和状态；默认按“最早到最新”处理。只有发布成功已核验后才推进游标；下载失败、上传失败或结果不确定都不得跳过候选或标记为已发布。
- 上传前以来源 URL/视频 ID、规范化标题、作者+歌名和已记录的媒体指纹做去重；下载目录中的旧文件只是临时输入，不能因文件名或本地存在就当成新候选。

## Select and score candidates

- 先过硬门禁：核心事实可回溯、来源和日期明确、音频/画面可合法使用、没有未处理的隐私或高风险主张；任一失败都不进入脚本。
- 在 `media-ops` 通用分之外保留抖音专属判断：前三秒清晰度、完播潜力、画面/字幕可执行性、信息密度、评论话题和系列延展性。
- 绝对播放量、点赞量和热搜位置只作规模信号。优先选择能让陌生用户快速理解、看完有收获、愿意评论或收藏的主题；不要把“更高播放”写成“更适合账号”。
- 同一事件的转载、剪辑和评论聚为一个候选，优先引用最早或最权威来源；记录淘汰理由，不能为了凑数量降低事实或版权标准。

## Adapt into a short video

- 默认交付一份可拍摄脚本：标题/封面文案、时长目标、前三秒钩子、分镜、口播、屏幕字幕、画面素材、来源卡和结尾互动。
- 标题先读取账号平台风格中的模板；没有账号模板时，音乐现场默认使用“可搜索信息 + 可感知现场”的结构，不把所有作品写成同一个流量标题。
- 音乐现场标题通常按“艺人 live《歌名》｜现场亮点/情绪钩子｜活动名称 城市/站点 年份”组织；如果没有可核实的现场亮点，退回“艺人 live《歌名》｜现场版｜活动名称 城市/站点 年份”。
- 同一账号的音乐系列必须轮换情绪钩子：优先从歌曲主题、演唱细节、现场环境、听众反应或具体画面提炼，不要把同一句“让人慢下来”或同一套安静形容词复制到连续作品。
- “现场版”和“音乐实录”不必同时出现；标签通常按“艺人 → 歌名 → 活动/现场特征”排列，控制数量并避免重复标题正文。
- 现场亮点必须真实出现在视频中，例如全场合唱、雨中演出、观众互动、乐手独奏或明显的情绪变化；不得为了提高点击虚构氛围。
- 知识/科技口播优先采用“具体变化 → 证据 → 为什么重要 → 对普通人的影响 → 一个问题或动作”；每条视频只解决一个问题。
- 每个镜头写清画面、口播、字幕和来源。数字、专有名词、限定条件和“不确定”应直接上屏，避免只靠配音传递关键事实。
- 钩子必须具体且与正文兑现，不用“惊天内幕”“赶紧转发”等虚假紧迫感；不能把预测、营销话术或个人推断写成已发生事实。
- 口播先写可自然朗读的短句，再压缩字幕信息；字幕不得遮挡主体，画面变化要服务理解，不用无关素材填充时长。
- 结尾只设置一个具体互动入口，例如“你更在意速度还是成本？”或“要不要做下一集实测？”；系列内容要说明下一集解决什么问题。

## Produce and review

- 发布前检查：视频比例和时长、前三秒是否独立成立、口播是否能在目标时长内完成、字幕是否可读、关键事实是否有来源卡、音乐/画面/肖像是否有权限、账号身份是否正确。
- 外部下载的媒体先做本地资产验收，再进入上传：确认文件可播放、时长与候选一致、视频轨存在；音乐视频还必须确认音频轨存在且预览能听到声音。只看到“下载完成”或“上传成功”不能替代音视频验收。
- 若上传后的预览无声、时长异常、黑屏或画面与候选不符，立即停止发布；重新取得媒体后，通过“替换视频”重新上传，并等待新的上传成功状态和预览刷新后再次验收。不得用静音版本试发。
- 文件选择器失败时，先检查浏览器对本地文件访问和文件选择器的权限，再使用页面可见的上传/替换入口触发文件选择器；不要通过页面脚本提取或拼接受保护的第三方直链。上传恢复后重新走完整媒体验收。
- 使用 SnapAny 等下载页时，优先按页面可见控件操作：粘贴已核验的来源 URL，点击“提取视频图片”，等待结果卡片；在“下载视频”卡片旁点击向下箭头/`More options`，再点击菜单中的“备用下载地址”。不要猜测、复制或直接打开带签名的第三方媒体 URL。若备用地址打开新的结果页，重复定位该结果卡片的向下箭头，并对可见的“备用下载地址”等待浏览器下载事件；下载事件未完成前不得把媒体视为已取得。详细步骤见 [SnapAny 下载参考](references/snapany-download.md)。
- 下载失败、只打开媒体预览页或只留下 `.crdownload` 时，不得单次失败即跳过：先等待当前临时文件是否完成，再刷新 SnapAny 页面、重新粘贴同一来源 URL 并重新解析。按“正常下载按钮 → 刷新重解析 → 页面明确的备用地址/格式 → 刷新重解析 → 正常下载按钮”的顺序交替尝试；默认至少完成两轮交替，单次尝试最长等待 180 秒，最多 4 次有效尝试。每次都只操作页面可见控件，并记录方式、等待时长和结果。
- 只有在上述交替恢复全部失败、没有完整可播放文件且页面没有新的明确下载方式时才跳过本轮并记录原因；不得无限点击、猜测镜像地址或绕过访问控制。临时文件应写入受控临时目录，完成发布成功核验后只删除本次运行创建且已确认的文件，不清空整个下载目录。
- 需要外部素材时优先使用已授权素材、平台明确可用的音源或自行拍摄/录制内容；不得下载并重新上传无法确认授权的第三方视频、音乐或人物画面。
- 对用户已确认授权的创作者素材，来源 URL、授权范围、下载记录和作者署名保留在证据卡/状态文件中。抖音公开标题和文案默认不放外部来源链接、下载链接或“原视频：平台名”；可保留作者姓名作为署名，但只有授权范围和账号策略明确要求时才加入“授权转载”等表述，不得暗示与作者或原平台官方存在合作关系。
- 对商业合作、产品体验、股票或高影响主题，补齐必要披露，并把事实、推断和建议分开；不提供投资、医疗或法律结论。
- 发布后记录播放、完播/平均观看、互动、收藏、分享、关注转化和负向反馈，并按内容支柱、时长、首句、媒体形态和互动入口复盘。单条爆款不能单独证明某种模板稳定有效。

## Publish

- 通过受控登录会话发布时，先核对当前抖音账号与配置中的公开身份一致，再创建草稿。
- 创建草稿后重新读取标题、完整文案、媒体预览/时长/声音、可见范围、定位/话题和发布按钮状态；以这次读取结果为准，不凭记忆恢复用户删除的文案行或标签。若编辑器会追加而不是替换文本，先全选再输入最终文案，并重新读取确认没有残留来源链接。
- 抖音公开字段发布前检查 `http://`、`https://`、`www.` 和原始来源 URL；除非用户或配置明确允许，否则标题、正文、话题和置顶评论都不得携带外部链接。来源链接只留在证据卡、审计记录和顺序状态中。
- 发布前确认最终发布按钮的精确可访问名称、可见实例数为 1 且处于可用状态；若按钮数量不唯一或状态不明则停止。最终发布按钮只点击一次。点击后不要因页面跳转、按钮消失或短暂无提示而再次点击。
- 发布后等待页面完成跳转和异步刷新，再按证据强度核验：优先看作品时间线是否出现“标题 + 文案”的新条目，其次看作品总数是否增加、状态是否为“已发布”或“审核中”，最后才使用 toast/作品 URL 作为辅助证据。核验时记录发布时间和当前状态。
- 若作品时间线尚未刷新，先等待并重新读取页面；若仍无明确成功、审核中或错误状态，报告“已提交但结果待确认”，保留结果页，不盲目重试。只有明确失败且页面仍处于可编辑草稿状态时，才允许回到草稿修复后重新发布。
- 只有明确看到发布成功/审核中并能将其与本候选关联时，才写入顺序状态、推进 `nextVideoId` 并清理本次临时媒体；结果不确定时保留状态为待确认，不推进、不删除唯一副本。
- 交互式运行在最终发布前必须展示完整成稿并等待针对该账号和该内容的明确确认；已被有效无人值守调度调用的 `scheduled_run` 按 `media-ops` 门禁执行，不重复要求逐条确认。
