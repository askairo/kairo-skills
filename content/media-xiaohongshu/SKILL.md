# Media Xiaohongshu

本技能处理小红书平台策略、素材发现建议、平台筛选、改编和发布。`media-ops` 先传入账号目标、内容主体、受众、来源边界和发布策略；本技能据此生成小红书专属发现策略，再接收核验后的候选完成平台筛选和发布。

文本改编前必须读取 [copy-framework.md](references/copy-framework.md)。视觉质量不能替代文字的点击、读完和收藏理由；标题、开头、正文结构、结尾和标签必须作为一个整体校验。

## Build the discovery brief

- 先明确账号的搜索意图、内容主体和读者收益，再决定发现关键词、来源类型和候选形式；不把其他平台的热门帖子直接搬运为选题。
- 优先发现可被整理为清单、步骤、对比、避坑或经验框架的原始材料；用搜索相关性、收藏价值、信息密度和账号承接判断候选。
- 为每个候选记录来源、核心事实、读者问题、可收藏结构、图片/截图权限和搜索词边界；热度只作为新鲜度和需求强度的辅助信号。

## Adapt content

- 交付 3 个标题候选：明确主题、读者收益或认知差异，不用虚假夸张词。
- 标题必须在发布前校验为不超过 20 个字符（包括标点和 emoji）；编辑器出现 `超过 20`、`X / 20` 或类似校验提示时，先压缩标题再进入发布动作。
- 开头用 2—3 句完成“具体问题/反差 → 人物的一个判断或事实 → 这对读者有什么用”；禁止先写平台背景、账号背景或空泛赞美。
- 正文只围绕一个核心问题展开，按“事实/原意 → 核心判断 → 解释依据 → 可带走的启发”推进；短段落、小标题和列表优先。
- 优先提供可收藏的判断清单、思考步骤、对比或避坑建议；每张卡片只承载一个信息单元，卡片文字与正文结论一一对应。
- 人物观点系列优先采用“上下文一句话 → 人物原话/原意 → 理念解释 → 一句引导”的短结构：先说明网友或讨论背景，再说明段永平说了什么，最后用已核验的理念解释其隐含判断。外部资料只补足背景，不扩写成完整投资结论。
- 面向指定人物主题时，公开文本直接使用人物姓名和主题，不把来源平台、来源账号或其他平台生态写成主语；来源归属只在确有必要且配置允许时出现。
- 封面承诺必须由正文兑现；来源、日期、事实与个人判断清晰分开。
- 标签围绕真实主题，不堆叠无关热门词；商业关系、素材来源和必要披露必须明确。

### Visual consistency

- Netrix 封面采用低自由度固定模板，规范细节见 [netrix-cover-template.svg](assets/netrix-cover-template.svg)；不得只复用配色或临时凭感觉调整构图。
- 固定画布为 `1254 × 1254 px` 正方形；四边必须保留 `26 px` 米白外边，内容不得越过外边或圆角卡片。
- 固定几何：主体卡片 `x=26, y=26, w=1202, h=1202, rx=24`；正文安全区 `x=110` 至 `x=1144`；右上双圆固定在卡片右上并允许被卡片边界裁切；分隔线固定从 `x=110` 到 `x=984`。
- 固定色板：外边 `#F5F1E8`，主体深墨绿 `#143B3A`，主文字米白 `#F6F1E7`，眉题/分隔线金色 `#D7B16A`，外圆 `#C9A15F`，内圆 `#D8B778`。禁止自动取色、渐变、透明度漂移和相近色替换。
- 固定字体层级：macOS 优先 `PingFang SC`；眉题 `36 px / 500 / letter-spacing 5 px`，主题 `104 px / 700 / line-height 1.15`，辅助句 `38 px / 400 / line-height 1.65`。主题最多两行，辅助句最多两行，必须手动断行，不得溢出安全区。
- 固定布局顺序：左上眉题 → 右上双圆 → 左侧主题 → 金色分隔线 → 左侧辅助句；不得改成满版底色、无白边、底部贴边、不同眉题或复杂装饰。
- 内容与背景保持安全距离：主题、分隔线、辅助句均不得贴近卡片边缘；辅助句最后一行基线不得低于 `1040 px`，卡片底部至少保留 `188 px` 留白。
- 封面只承诺正文解释的一个问题；发布前必须校验尺寸、四边白边、圆角、六个固定色值、字号层级、两行上限和底部安全距离。

## Media and review

配图、截图、信息卡和视频必须真实、清晰、具备使用权限；不为凑九宫格重复或拼接无关图片。发布前检查标题、封面、正文、来源区、标签、账号身份和发布按钮；发布按钮只点击一次并等待明确结果。

- 发布前重新读取编辑器中的最终标题、正文和媒体状态，确认标题长度校验已通过。
- 点击发布后只接受明确的成功提示、已发布状态、帖子 URL 或账号时间线新内容；如果页面仍停留在编辑器、出现校验错误或状态不明确，记录为“发布未确认”，并在运行记录中保留具体页面信号。
- 只有当本机执行策略明确配置 `retry-on-failure` 时，`publish_failed` 或 `publish_unconfirmed` 才允许在后续运行重试；每次最多点击一次，重试次数遵守配置上限（未配置时默认不重试）。账号不匹配、事实/版权门禁失败、安全验证和验证码不可重试。
- 发布未确认时，不得把候选写入已发布清单或推进来源游标；达到重试上限后暂停该候选，避免重复发布。
