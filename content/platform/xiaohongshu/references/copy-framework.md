# 小红书图文文本框架

## 适用目标

这套规范用于“人物观点、商业思维、企业观察”类图文。目标不是复述来源，而是把一个可核验的公开表达，整理成读者愿意点开、读完、收藏并参与讨论的单一问题答案。

小红书的选题与文本同时服务于搜索和推荐：平台公开规则显示，热点排序会综合搜索、传播、互动和点击；平台审核也要求标题、封面与正文一致，禁止夸张标题、蹭热度和对其他相似平台的过度探讨。因此文本要具体、可检索、有信息增量，但不能用平台名或夸张承诺代替内容价值。

## 一篇笔记只讲一个问题

发布前先写一句“这篇笔记回答什么问题”：

```text
读者问题：________？
核心结论：________。
读者看完能带走：一个判断 / 一张清单 / 一个方法 / 一个反思角度。
```

如果同一素材同时包含多个问题，拆成系列，不在一篇笔记中堆叠背景、人物经历、公司分析和投资结论。

## 先把“信息”变成“张力”

清楚不等于好看。动笔前再补一句：读者为什么会在这一条停下来？从下面选择一个主要张力，不要同时堆叠：

- **反差**：大众直觉与人物判断哪里不一样；
- **选择**：两个看似都合理的做法，真正差别在哪里；
- **后果**：忽略这个判断，现实中容易付出什么代价；
- **场景**：一句对话、一个动作、一个数字或一个具体公司，把抽象概念落地；
- **误读**：一句话最容易被怎样理解错，完整上下文又说明了什么。

如果只能写出“某人谈某事”“某事怎么看”或“这给我们什么启发”，说明张力还没有找到，暂不进入成稿。

## 标准文本结构

### 1. 标题：关键词 + 张力 + 明确收益

- 提供 3 个候选，最终只选 1 个；不超过 20 个字符。
- 3 个候选必须来自三种不同路径：冲突/反差、动作/场景、读者判断收益；不得只替换同一问句中的主题词。
- 标题优先出现内容资产中的核心人物或主题关键词。
- 人物名不是固定前缀。最近 5 条已经频繁使用人物名前缀时，让公司、场景或冲突承担点击理由，人物归因放入开头。
- 用具体问题、反差、判断或结果制造点击理由，不用“震撼”“绝了”“必看”“全网都在”等空泛词。
- 标题必须准确承诺正文会回答的问题；不能用热点人物或平台热度吸引点击后讲别的内容。
- 生成前对照最近 5 条标题，禁止复用“人物名：X看什么”“为什么X”“真正的X”等相同骨架；相同关键词连续出现时也要换角度，而不是只换标点。

可用结构：

```text
别急着改变别人
授权到期，风险才刚开始
一份承诺，先看谁承担代价
```

### 2. 开头：三句内让读者进入问题

```text
第 1 句：给出具体场景、矛盾、意外判断或现实后果。
第 2 句：用最短必要事实或人物原意把悬念落地。
第 3 句：说明真正值得拆开的那一层，而不是宣布“本文将介绍”。
```

禁止用“今天给大家分享”“相信很多人都知道”“在某平台上，某账号发布了……”作为开头。

第一句应当脱离标题也能成立。优先使用具体名词、动作和数字，少用“本质、逻辑、价值、意义、值得思考”等抽象词。允许有限的编辑存在感，例如“我更在意的是……”或“有意思的不是答案，而是他先排除了什么”，但不得虚构亲历或替人物补写态度。

### 3. 正文：按素材选择叙事方式

事实、人物原意、编辑判断和读者启发必须分开，但不再要求每篇都套同一个“四步”或“三步判断”。从以下结构中选择最适合素材的一种，并避免与上一条重复：

1. **对话切入**：保留一句有张力的问答 → 解释为什么这句回应出人意料 → 给出适用边界；
2. **反常识转折**：先写常见直觉 → 给出人物不同判断 → 解释差异来自哪个前提；
3. **选择冲突**：摆出两个真实选项 → 说明各自代价 → 给读者一个判断锚点；
4. **案例拆解**：从公司、动作或数字开始 → 回到人物原意 → 提炼有限结论；
5. **纠正常见误读**：先写最容易误读的结论 → 补足上下文 → 说明什么能说、什么还不能说。

无论选择哪一种，都遵守：

```text
必要上下文：只保留理解判断所需的具体信息。
人物原意：最短必要引语或准确转述。
编辑增量：解释前提、边界、冲突或可复用判断。
读者落点：一句可带走的话、一个回扣或一个具体问题。
```

每段只完成一个任务，长短句交替，读出声应当像人在解释一个有意思的发现，而不是运行报告。默认正文控制在 220—420 字；素材很短时宁可更短，不为了“完整”堆背景、资料和多条建议。事实、人物原意和编辑解读必须分开，不用“人物认为”替代证据，也不把编辑推断伪装成人物原话。

### 4. 结尾：留下余味，不固定求互动

在三种方式中轮换：一句明确的带走结论、回扣开头的反差、一个真正值得回答的具体问题。问题不是必填项；没有自然问题时，用一句有边界的判断收束。不要使用“点赞收藏关注我”“评论区扣 1”等机械求互动话术。

### 4.1 收藏与分享价值门禁

每篇笔记至少提供一个读者可以带走、复用或转给特定对象的具体单元，四选一；它可以写成自然段，不强制编号：

- 一个判断顺序：先看什么，再看什么，最后避免什么；
- 一张短清单：适用条件、关键问题和常见误区；
- 一个对比框架：两种选择分别适用于什么情况；
- 一句可复述的原则：不能只写漂亮金句，必须有上下文和使用场景。

“值得收藏”“转给需要的人”不能代替实际价值。若使用问题结尾，只保留一个，并让问题自然承接上述判断或清单；不同时堆叠收藏、转发、点赞和关注请求。发布前检查：读者是否能说明“我为什么要保存这篇”，以及是否能指出“我会转给哪类人”。

## 趣味性与去模板化门禁

成稿后与最近 5 条公开文案对照：

- 标题、第一句、正文推进方式和结尾方式至少有两项明显不同；
- 至少有一个具体细节：对话、动作、公司、数字、代价或选择；
- 至少有一句离开原帖摘要后仍值得复述，但它必须有上下文，不能只造金句；
- 删除“这告诉我们”“值得我们思考”“从本质上看”“首先其次最后”等报告腔，除非替换后会损失准确性；
- 不连续使用“三步判断”“先看什么”“人物名：……”等同一骨架；
- 朗读一遍：如果像会议纪要、分析模板或机器摘要，必须改写后再发布。

### 5. 标签：主题词、问题词、场景词

通常使用 4—6 个标签，优先覆盖：

- 人物词：与内容资产中的人物一致
- 主题词：`#长期主义`、`#企业经营`
- 问题词：`#商业思维`、`#管理思考`
- 场景词：根据正文选择 `#投资思考`、`#创业思考` 等

标签必须与正文真实相关；不使用来源平台名、无关热词或为了扩大曝光而堆叠的泛标签。

## 发布前文字门禁

逐项确认：

- 标题不超过 20 个字符，且标题、封面、正文回答同一个问题。
- 开头 3 句内出现具体问题、人物的事实/判断和读者收益。
- 正文结构与素材匹配，并与上一条明显不同；事实/原意、编辑判断和可带走信息仍有清楚递进。
- 删除平台名、账号名、来源叙述和与主题无关的背景；内部来源记录不等于公开文案。
- 所有引语、数字、时间和人物归因可回溯；推断使用边界词。
- 没有绝对化、夸张、收益保证、荐股或机械求赞求收藏表达。
- 结尾采用带走结论、回扣或至多一个具体问题；标签 4—6 个且与正文一致。

## 复盘指标

不要只看阅读量。按“曝光 → 点击 → 读完/停留 → 点赞 → 收藏 → 评论 → 关注”拆解：

- 曝光低：检查主题词、标题关键词、账号垂直度和发布时间。
- 点击低：检查封面与标题是否给出具体问题和清晰收益。
- 阅读/收藏低：检查开头是否过长、正文是否提供可复用结构。
- 评论低：检查结尾是否提出了具体取舍问题，而不是泛泛求互动。

每次只调整一个变量，连续观察同一类型笔记，不用单篇爆文推导稳定规律。
