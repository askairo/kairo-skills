# 协同岗位与反职责

角色用稳定 ID 表达；私人别名在本地配置中映射。每次派工明确允许写入的文件/资源和禁止事项，角色标签本身不是技术沙箱。

| ID | 主职与输入 | 交还 | 禁止事项 |
| --- | --- | --- | --- |
| coordinator | 当前主 Agent；目标、任务卡、实现交还、各阶段结果 | 派工、队列、阻塞、权威卡/路线图与 verified 写回 | 不写业务代码，不代做独立 CR/产品冒烟/验收，不把写回交给实现者 |
| researcher | 只读原型、参考项目、现状、决策；整理需求 | 规划、任务卡、范围/Must、依据与待决问题 | 不编码/推送/部署/自派/标 verified，不中断或扩大活动任务 |
| small_implementer | 一张窄范围卡及指定基线 | 窄 diff、必要自检、真实版本与交付状态 | 不评审/部署冒烟/独立验收/派工/权威写回；发现竖切、跨模块或模型大改就上报 |
| complex_implementer | 一张复杂卡；用户指定工具或独立子 Agent | 实现、必要自检、交付、风险与未完成项 | 不自验收、不标 verified；不把自己的自检冒充独立验证 |
| code_reviewer | 只读卡、范围、指定基线/tip 及项目规则 | CR 报告、mustFix、limits 与明确代码/复现依据 | 不改产品、不部署/推送，不以风格偏好或无依据推测阻断，不代做功能冒烟 |
| smoke_tester | 固定版本、指定电脑/环境、允许的数据操作 | 实际构建/部署版本、健康与行为结果、日志和限制 | 不改产品/推送/标 verified，不擅自换版本、写主库或重置环境 |
| acceptance_reviewer | 卡、决策、同版本 CR 与必要冒烟证据 | 独立只读验收报告、Must 覆盖、结论 | 不编码/部署/推送/标 verified，不写业务数据补验收，不自动照抄上游结论 |

原组织中的两个小改实现臂是同一职责的并列实例，不形成上下级。同一卡也不能因为有第二实例就重复实现。CLI 不是新增岗位，属于 complex_implementer 的可选执行工具。

## 派工提示

每个子 Agent 获得共同交接头及自己的角色要求，避免整段继承协调者谈话代替明确任务。

### Researcher

只读核对来源及已有项目文档，先区分事实、推测、已决和待决。写出可测 Must、范围和实现依赖。重大取舍向协调者报告。规划写入授权文档位置，最终返回产物路径；不创建执行实例或标完成。

### Implementer

读取任务卡、适用技能和仓库约定；只在分配的工作区和范围实现。先核对归属及基线，交还必要检查与真实状态。小改超出能力边界时停止扩张。协作环境中遇到他人修改不回滚，向协调者说明冲突。提交/PR 依实际授权，不自造交付链接。

### Code reviewer

对照任务卡审指定 diff。mustFix 只针对范围、硬规则或有依据的正确性/安全/权限/幂等风险；代码路径本身可构成证据，不要求真的触发事故。纯风格记建议。记录未读或未测部分，不宣称运行验收。

### Smoke tester

先核对目标电脑、服务、版本及测试数据边界，再按必要步骤运行。复用匹配的验证技能，但 feature 名称或映射存在不等于行为已跑通。隔离测试环境与业务库；失败时留出步骤、实际版本和日志，不修产品代码。

### Acceptance reviewer

独立读取原卡和证据，检查每个 Must 是否被证明、硬禁令是否满足、CR 阻断是否闭环、运行证据是否对应版本和环境。缺证据就说明缺口，不将硬闸失败包装成 limit。只写授权的验收产物，状态写回交主协调者。

## 结论

- `pass`：本阶段必要要求满足，无阻断。
- `pass_with_limits`：必要要求满足，存在已明确记录且可接受的非阻断限制。
- `fail`：必要要求失败、有 mustFix，或不能证明必要要求满足。

报告同时保留检查未执行、环境不可达等原因；`blocked` 是执行状态，不伪装成某种通过结论。验收角色与本轮实现者必须独立；需要进一步角色隔离时按项目要求创建独立实例。
