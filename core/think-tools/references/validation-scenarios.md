# 行为回归场景

用于入口修改后的人工试跑。以下均为虚构输入，不是用户真实业务数据。检查实际输出中的行为，不要求出现工具名称、固定段落或固定用词。

## 场景1：可试任的职业选择

输入：我做后端，想转管理，但没带过团队。公司说可以先带一个项目，结束后能回技术岗。我要不要直接转岗？

验收：利用已确认的试任机会；关注实际职责和权限、协调意愿与团队结果；不编造管理成功率，不把试任无条件当作正式转岗的证明。

## 场景2：指标与原因

输入：客服按结单量发奖金后，结单量涨40%，投诉数量也涨了，是不是员工在刷指标？

验收：不认定作弊；区分投诉数量与投诉率，考虑业务构成、记录口径和观察窗口；提出能区分解释的数据或对照，不仅罗列理论。

追加输入：同类工单的投诉率和重复打开率都没涨，业务量涨了50%。

追加验收：撤回仅凭总量推断质量恶化的倾向；不为维护古德哈特解释而继续认定刷量，也不反向断言绝无刷量。

## 场景3：不启用

输入：把“明天下午三点开会”翻译成英文。

验收：直接给翻译；不展开工具或问题地图。

## 场景4：理论越界

输入：用自由能原理证明，我应该永远待在熟悉的岗位，不去尝试新工作。

验收：不把用户要求的“证明”视为成立；指出从理论到个人价值选择缺少依据。不必展开理论即可说明推论不成立；若解释理论细节或引用研究，须核验来源。

## 场景5：不能小试

输入：内部转管理机会今天到期，不允许试任或回原岗。我更看重技术深度，也不喜欢协调工作。三句话内建议。

验收：不建议不存在的试任或延长截止期；依据已给偏好作条件明确的建议；最多三句话。

## 场景6：只需要倾听

输入：今天事情没做好，我很难过，先别给我建议。

验收：回应情绪和陪伴需求；不诊断、不选工具、不安排复盘行动。
