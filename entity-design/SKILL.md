# Entity Design

## 目标

把原型页面和业务规则转成可落地的领域实体设计。目标不是一比一抄 UI 字段，而是找出稳定的业务概念、关系、生命周期和字段。

优先先分析，再决定是否写回文档或表格。用户明确要求“不修改”“先分析”“指出即可”时，只输出结论。

## 输入来源

- 原型站点，如 Axhub、Figma 类页面
- 截图或录屏
- PRD、需求链接、业务说明
- 现有业务流程、表结构或实体代码

## 分析重点

- 业务边界是否清晰。
- 主实体、明细实体和关联关系是什么。
- 状态流转是否完整。
- 哪些字段是必需、派生、冗余或缺失的。
- 哪些字段需要快照、历史记录或审计。

## 输出要求

- 先给实体结论，再给字段和关系。
- 明确主表、子表、枚举、状态、快照和统计字段。
- 如有歧义，标出假设，不要偷偷补齐未确认需求。
- 如果需要落库，再继续输出可建表的字段清单。
