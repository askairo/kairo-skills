# 宿主能力与实际搭建

本文件定义适配步骤，不自带 Grok Bot、Hermes 或任一 CLI 的私有 API。先发现当前提供的连接器、工具、CLI 和官方文档，再选择可执行入口；宿主产品名不证明创建、消息或后台能力存在。

## 子 Agent 宿主

1. 核对当前是否能创建独立上下文、传入职责与任务、接收结果、查看/停止实例；能力名依实际工具，不硬编码其他平台的调用名。
2. 能力未启用时依官方文档启用；需扩展时仅按官方提供或官方文档给出的方案安装，再用无外部副作用的小任务验证。无可用官方方案就报告缺口，不把第三方包称为官方能力。
3. 个人工程读取并复用现有 `t-loop`。没有安装时走 `skills-loop` 安装；需要生成或修改通用流程时走 `skill-creator` 和 `skills-loop`，不另造同义技能副本。用户机器路径与角色别名按 `t-loop` 自己的 schema 写入其唯一配置位置。
4. 把团队规范、岗位提示词、协作契约和维护入口保存到外部记录；按宿主支持方式提供给主 Agent 和子 Agent。临时派工应传当前岗位规范与产物路径，不假定子 Agent 继承全部技能和历史。
5. 验证独立结果是否返回主会话、实现者与验收者是否独立、共享工作区如何隔离、暂停是否阻断新派工。记录实际执行范围，测试样例不代表真实项目全流程已跑通。

当前安装的 `t-loop` 是工程规范来源，不把源码包路径当作固定运行位置。缺少工具时可以生成产物，但配置/运行状态保持未完成。没有停止/释放 API 时如实记录宿主限制，不宣称销毁了会话日志。

## 原生 Bot 宿主

1. 清点现有 Bot、职责档案、技能、协作关系和唤醒配置。识别符合岗位的可复用实例；同职的多个执行实例不自动算冗余，不因名字不同重复建岗位。
2. 明确本次哪些 Bot 允许创建或调整、是否允许配置定时/事件唤醒和发送验证任务。只授权设计或审核时，交付配置草案；用户已授权搭建时，在范围内直接完成可逆创建与配置。
3. 优先用实际可用的宿主 API/CLI/连接器；能力不足再用可用 UI。没有可用入口时生成完整角色文件、关系与未应用清单，记录阻塞，不假造平台 API、实例 ID 或“已自动搭建”。
4. 为所需岗位创建/更新配置，包括 dr eggbot 维护者。逐个写入并回读职责、反职责、语气、唤醒、技能/材料引用及协作对象；记录创建前基线、真实 ID、差异与回退方式。
5. 保留宿主原生 Bot 派工、通信和状态机制，不因安装 `t-design` 或项目需要协同就启用 `t-loop`，也不为 Bot 体系额外安装子 Agent 扩展。工程版沿用唯一实现者、独立验证和唯一项目状态写回者的契约，但实现为原生 Bot 关系。
6. 在用户授权的测试目标、消息范围与数据边界内验证实际交接。未做消息/运行测试就只写 configured；不为补证据擅自启动生产任务、例程、仓库监听或恢复暂停项目。

配置、创建、公开分享和实际启动是不同动作。Bot 分享按钮、账号绑定、凭证设置与扩大访问范围不能由普通职责设计自动授权。平台要求额外确认或用户操作时，先完成可复核产物，再说明具体剩余动作。

## 并发与回滚

- 活动项目的范围、唯一实现负责人和验证版本受原协调者管理；维护者不得在后台替换正在执行的配置。
- 待生效版本先与在用版本分开；采用版本号、摘要或平台修订号，并记录生效时点。恢复时重新读取真实配置，不只相信旧检查点。
- 回滚按记录恢复本轮改变的配置，保留证据；不要删除既有 Bot、会话、共享技能或无关工作树作为“重置”。不可逆删除另按明确授权处理。
