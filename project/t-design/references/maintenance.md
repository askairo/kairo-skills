# 维护、审核与有界优化

## 两种模式

| 请求 | 可执行动作 |
| --- | --- |
| 讨论、设计、审核 | 读取现状、产出设计/问题/建议与证据；不因发现问题自动修改目标、发布、安装或创建 Bot |
| 搭建、修订、维护 | 在用户已授权的对象、操作和范围内生成、修改、验证并应用；已明确授权的发布/安装继续执行，无需每一步再确认 |

模式来自本次和仍有效的用户授权，不由技能自行授予。可以记录持续维护范围，但配置中的一句“自动优化”不能扩大权限。发布通用规范不表示可以公开用户团队实例、私人模板或历史对话。

## 每轮优化

1. **收集真实反馈。**读取交还、失败步骤、角色配置、运行版本和验证记录。标明事实、推断、建议、未验证能力；仅有抱怨或自评“通过”时先核对依据。
2. **确定问题归属。**业务缺陷/产品验收交项目协调者；职责重叠、越职、交接缺项、工具适配或技能规则缺陷属于维护者。普通项目进度不自动触发规则改写。
3. **定义候选调整。**绑定问题 ID、对象及基线版本、允许的变更、可观察成功条件、回退方法和本轮停止条件。选择足以解决问题的最小修改，不把单次故障扩展为所有项目永久禁令。
4. **隔离生成与验证。**候选规范不覆盖活动任务的在用版本。复杂流程使用独立审核者和原始场景核对实际决策；简单说明或格式调整做相称检查。缺子 Agent 能力时不能用同一会话自称独立审核；原生 Bot 用其实际验证入口。
5. **按范围应用。**Bot 岗位变更回读真实配置；共享技能先依 `skill-creator` 修源码，再走 `skills-loop` 校验、提交/推送、回装和一致性检查。明确哪些目标已同步、哪些仍是旧版；不能把一个宿主成功推广为所有宿主已验证。
6. **观察并结束或续轮。**依据新的执行证据判断改进是否有效。没有新证据或没有待解决问题时收束记录，等待下一次触发；不要为了“loop”重复运行、制造任务或无限创建审核者。

用户暂停、授权范围耗尽、连续同因失败且无新信息或关键决定缺失时停止依赖动作，保存恢复点。没有自动调度器就只在当前会话内推进；周期巡检、Webhook 和后台常驻须另有明确需求与实际配置。

## 审核输出

每个发现写明目标用途、依据位置或复现步骤、实际后果、严重度和建议。区分必须修复的职责/正确性问题与可选风格建议。给出与验证版本绑定的结论和未覆盖部分，不把文档存在、API 返回成功或旧版本通过当作当前行为证明。

dr eggbot 维护体系状态和技能记录，不替工程协调者派产品实现，也不将项目卡写成 verified。维护者可以修改获授权的技能代码/脚本与配置；“不做编码工人”针对长期业务实现职责，不妨碍履行技能生命周期工作。
